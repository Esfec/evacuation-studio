## 已通过的逐步一致性检查

- 每帧 48 个 Agent 身份完整，Active / Escaped / Dead / Exhausted 汇总与快照一致。
- 房间占用数与 Active Agent 的实际位置一致，未超过房间容量。
- 每次 `MOVED` 都沿真实拓扑边移动，目标与最终位置一致。
- 每条通道的 `proposals = accepted + edge_queue + node_full`，接受人数未超过单步容量。
- 实际移动人数与通道 `accepted` 记录逐步一致。
- 没有选择当步不可通行目标，没有关闭路线被兜底恢复的迹象。
- 健康、体力、恐慌值均在合法范围；健康未回升、烟气累计暴露未倒退。
- 终止状态不可逆，没有死亡后复活或逃生后返回。
- 单个 Agent 最长连续通道排队为 2 步；排队资历连续，没有长期饥饿。

## 确认的问题：DeepSeek 目标字段不符合协议

系统要求：`{"target_id":"N02", ...}`。

部分 DeepSeek 响应却返回：`{"target_id":"过厅", ...}` 或 `{"target_id":"主大厅", ...}`。语义选择通常合理，网络请求也成功，但严格校验无法把中文房间名当作节点 ID，所以记为 `invalid_target`。

- N06 轮：17 次无效尝试，最终 F29、F41、F42、F44 在第 0 步使用规则兜底。
- N01 轮：12 次无效尝试，最终 F39、F46 在第 0 步使用规则兜底。
- 没有鉴权、网络、限流或 JSON 解析错误。

当前重试会把原提示原样再发一次，没有告诉模型“刚才把房间名写进了 target_id，请改成 Nxx”，因此同一 Agent 可能连续三次犯同一错误。这是需要修复的交互协议问题，也是额外 token 消耗的来源。

## 决策构成与实验解释

N06 轮共有 387 个有效决策记录：278 次直接采用 LLM、4 次规则兜底、105 次恐慌机制覆盖。N01 轮共有 368 个：268 次直接采用 LLM、2 次规则兜底、98 次恐慌机制覆盖。

恐慌覆盖是当前模型的既定行为机制，不是日志丢失；但论文中应明确区分“LLM 给出建议”和“最终动作被恐慌机制改写”。否则会高估 LLM 对最终轨迹的直接控制比例。

## 关于死亡人数

N06 轮死亡 26 人，其中 Follower 23 人、Perceptual 3 人、Cognitive 0 人；N01 轮死亡 20 人，其中 Follower 18 人、Perceptual 2 人、Cognitive 0 人。死亡发生在第 6 至 17 步，累计烟气暴露达到约 3.0 以上后陆续出现，没有首步死亡、负健康值或集中在一个异常节点的迹象。

这说明高死亡率主要来自当前 Follower 的低体力、低抗压、较强从众和高错误覆盖参数，与逐步记录一致。目前证据不支持“死亡计数 bug”，但参数是否符合目标人群仍需通过多随机种子校准，不能由单轮运行判断。

## 使用限制

- 两轮起火点分别为 N06 和 N01，不能把 45.8% 与 58.3% 逃生率直接当作策略优劣对比。
- 两轮都有规则兜底，质量已降级；正式实验宜修复输出协议后重跑。
- 单个 seed=42 只能验证一条随机轨迹，不能支持统计结论。
